# Laws of UX: checklist

Summaries of well-established principles (see lawsofux.com for sources). Each line: the law, then what to do.

| Law | What it says | Apply it |
|---|---|---|
| **Fitts's law** | Time to hit a target grows with distance and shrinks with size | Big primary buttons, close to where attention already is. Edges and corners are easy on desktop |
| **Hick's law** | Decision time grows with the number and complexity of choices | Fewer options per step; highlight a recommended one; progressive disclosure |
| **Jakob's law** | People expect your site to work like the sites they already use | Logo top-left links home, cart top-right, standard icons and patterns. Innovate on value, not on navigation |
| **Miller's law** | Working memory holds a few chunks | Chunk phone numbers, steps and long lists into groups |
| **Cognitive load** | Mental effort to use the interface | Remove, then group, then hide. Defaults for common cases |
| **Tesler's law** | Complexity cannot be removed, only moved | Move it to the system: smart defaults, autofill, inference |
| **Gestalt: proximity** | Things close together are seen as related | Space within groups smaller than space between groups |
| **Gestalt: similarity** | Things that look alike are seen as related | Same style for same function; links all look like links |
| **Gestalt: common region** | Things inside a boundary are grouped | Cards and panels for related content |
| **Von Restorff effect** | The item that differs is remembered | One accent colour for the primary action only |
| **Serial position effect** | First and last items are remembered best | Put key nav items and key points at the start and end |
| **Peak-end rule** | Experiences are judged by their peak and their end | Design the success state and the final step with care |
| **Zeigarnik effect** | Unfinished tasks stay on the mind | Progress indicators, checklists, "2 of 4 complete" |
| **Goal-gradient effect** | Effort increases near the goal | Show progress, start people partway (step 1 already done) |
| **Doherty threshold** | Productivity rises when responses come under about 400 ms | Instant feedback, optimistic UI, skeletons for slow loads |
| **Aesthetic-usability effect** | Attractive designs are perceived as easier to use | Polish matters, but never let it hide a usability problem |
| **Postel's law** | Be liberal in what you accept | Accept many input formats (dates, phone numbers), normalize them |
| **Parkinson's law** | Tasks fill the time available | Autofill and short flows make tasks feel faster |
| **Choice overload** | Too many options lowers satisfaction and conversion | Curate. Compare 3 plans, not 7 |
| **Social proof** | People follow what others do | Real logos, numbers and named testimonials near the decision point |
| **Anchoring** | The first number seen sets the frame | Show the most complete plan first or annual savings against monthly |
| **Loss aversion** | Losses weigh more than equal gains | Frame honestly around what users keep or avoid; never fake scarcity |
