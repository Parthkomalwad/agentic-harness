# Launch

Everything comes from the real project. Read the code, README, CHANGELOG and demo output first. Never claim a feature you have not found.

## 1. Positioning (one screen)
Who it is for, the problem in one sentence, what it does about it, the one result that proves it (a number, a before/after, a demo). Ask the user to confirm before writing anything else.

## 2. Assets
- **README**: if it does not explain the project in ten seconds, use the `docs-pack` readme skill.
- **Launch video**: if `motion-pack` is enabled, write the brief for `motion-reel` (hook, 3 features, proof, call to action).
- **Blog post** (`docs/launch/blog.md`): title that states the outcome; problem, the approach, how it works (with a diagram or code), results, how to try it, what is next. 800 to 1,500 words. Real commands that work.
- **Social posts** (`docs/launch/social.md`): one X or LinkedIn post (hook in the first line, one visual, one link), one thread of 4 to 6 posts, one Show HN style title and first comment, one Reddit post adapted to the subreddit's rules.

## 3. Checklist
Repo topics and description set, license present, a release tag, demo link works, install command tested from a clean machine.

Write in plain language. No hype words ("revolutionary", "game-changing"). Follow the repo's writing rules, for example no em dashes.
