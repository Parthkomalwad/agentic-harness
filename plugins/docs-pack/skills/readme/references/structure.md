# README structure

Use the sections that apply, in this order. Skip any with nothing real to say.

1. **Header (centered)**: hero image, project name if the hero does not show it, one-line tagline as `###`, badges, a link row separated by ` · ` (Docs · Quick start · Contributing).
2. **What it solves**: the problem in two or three sentences, then what the project does about it. Follow with one bold callout blockquote that states the key promise.
3. **Features**: 4 to 7 bullets. Bold lead phrase, then one sentence.
4. **Quick start**: prerequisites, install, first run, expected output. Under 10 lines of commands.
5. **Usage**: the 3 to 5 most common tasks, each with a command and its output.
6. **How it works**: a diagram or a short tree of the layout, and a table of the parts.
7. **Configuration**: a table of options with default values.
8. **Roadmap or status**: a table, or a link to ROADMAP.md.
9. **Contributing**: one paragraph and a link to CONTRIBUTING.md.
10. **Security**: only if the project runs code, handles keys or touches user data.
11. **License**: one line.

Tagline formula: what it is + for whom or where + the single outcome. Example: "The Docker sidecar that gives any backend automated, encrypted database backups. Zero code changes."
